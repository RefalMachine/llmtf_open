# Shlepa: few-shot протокол

Все четыре registry ID (`shlepa/moviesmc`, `shlepa/musicmc`, `shlepa/lawmc`,
`shlepa/booksmc`) используют `ShlepaSmallMMLU`. Вопрос содержит 12 вариантов:
четыре исходных и восемь distractors из пяти других записей train. Accuracy
сравнивает gold с буквой, получившей максимальную token probability.

Если `correct_answer` содержит текст ответа, он сопоставляется только с
`answerA`–`answerD`; совпадение должно быть единственным. Нераспознанные или
неоднозначные ответы пропускаются. Исправление также устраняет прежнюю
зависимость такого сопоставления от порядка колонок и ложное совпадение с
самим полем `correct_answer`, поэтому может влиять и на zero-shot результаты.

## Демонстрации

`few_shot_count=k` добавляет k полных пар user/assistant перед оцениваемым
вопросом. Ответ демонстрации имеет вид `Ответ: X`, где X — правильная буква
после перемешивания вариантов. Оцениваемый вопрос заканчивается незавершённым
assistant `Ответ:`; его gold не включается в промпт.

Выбираются первые k пригодных вопросов train с различающимися текстами.
Для сравнения вопросов нормализуются регистр и пробелы. Вопросы демонстраций,
включая дубликаты их текстов, исключаются из evaluation; лимит
`max_sample_per_dataset` применяется после этого исключения. Поэтому состав
evaluation зависит от k. Исключение совпадающих текстов не является аудитом
семантически близких вопросов.

Demonstration choices перемешиваются отдельным RNG с seed 555 и одинаковы
между примерами и запусками с разным sample limit. Общие оценочные вопросы
при одинаковом framework seed сохраняют свои варианты и gold между 0/1/5-shot.
Distractors по-прежнему выбираются из полного train, независимо от лимита
evaluation. Данные берутся из существующего датасета без новой revision pin.

Нельзя молча уменьшать k: отсутствие нужного числа пригодных демонстраций,
отсутствие evaluation после их исключения или превышение prompt budget
завершают задачу ошибкой. Если backend не умеет считать токены, все k примеров
сохраняются; возможное превышение серверного контекста остаётся ошибкой backend.

## Настройки и артефакты

В основном Foundational-конфиге и legal Foundational Shlepa использует 5-shot.
В legal Instruct LawMC явно использует 0-shot. Если YAML не задаёт
`few_shot_count`, действует default evaluator CLI — 5. В частности, в текущих
основных Instruct YAML группа Shlepa не задаёт этот параметр и теперь получает
настоящие пять демонстраций. Для zero-shot задайте `few_shot_count: 0` явно.

Sample содержит `_shlepa`: индекс оценочной записи, индексы демонстраций,
requested/effective shots и длину полного промпта. `_params.jsonl` и
`_total.jsonl` сохраняют версию `shlepa_train_demonstrations_v1`, политику
выбора примеров, overflow policy, dataset identity и source digest.

До исправления от 2026-10-02 параметр `few_shot_count` игнорировался для всех
четырёх задач. Старые результаты с записанным k>0 фактически были zero-shot
и требуют пересчёта для настоящего few-shot baseline. Новый source digest и
provenance не позволяют использовать их как совместимый кэш. Сохраните новый
запуск в отдельный каталог или явно примените `--force_recalc`.

Технические проверки и точные команды:
[репорт исправления](../dev/SHLEPA_FEW_SHOT_FIX_REPORT.md).

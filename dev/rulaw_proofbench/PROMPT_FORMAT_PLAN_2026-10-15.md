# Новый формат промптов RuLaw expanded

Дата: 2026-10-15. Версия исполнения: `expanded_structured_v2`.

## Принятое решение

Новый формат заменяет прежний для всех четырёх задач
`rulaw_proofbench_expanded/{closed,grounded,mcq_closed,mcq_grounded}`.
CLI, состав 505 test + 20 train и фиксированные пять демонстраций сохраняются.
Старые задачи `rulaw_proofbench/*` на 194 вопросах используют прежние промпты.

Преобразование выполняется детерминированно при сборке сообщений:
[рендеринг](../../llmtf/tasks/rulaw_proofbench/prompts.py),
[open-задача](../../llmtf/tasks/rulaw_proofbench/task.py),
[MCQ-задача](../../llmtf/tasks/rulaw_proofbench/mcq.py).
LLM, перефразирование и семантический разбор не используются.
Отдельных флагов или новых имён задач нет.

Исходные Parquet, опубликованная revision и manifest не меняются.
В них остаётся исходный `prompt_version=expanded_v1`; эффективный
`prompt_version=expanded_structured_v2` записывается в task provenance
и `_rulaw_proofbench` каждого sample. Там же фиксируется
`assistant_prefill=null`, а provenance включает SHA-256 рендерера.
Старые результаты не являются результатами нового протокола; для нового
запуска нужен отдельный каталог либо явный force-recalculation.
Существующие исторические отчёты не переоцениваются автоматически.

## Автоматическое преобразование

У всех 525 текущих записей проверена структура `case_text`:

1. первая строка — акт, статья, дата оценки;
2. вторая — исходная область рассмотрения;
3. промежуточные строки — исходные обстоятельства;
4. последняя — исходный вопрос либо название запрашиваемого результата.

Рендерер проверяет исходную версию, первую строку по метаданным,
непустые компоненты и число строк `len(facts) + 3`.
Несоответствие вызывает ошибку с ID записи, без попытки угадать структуру.

Область рассмотрения и target не переформулируются. Обстоятельства
сохраняют порядок и получают только маркеры списка. Нельзя сопоставлять
их с порядком ключей `facts`: эти порядки совпадают не во всех записях.
Известные и неизвестные обстоятельства остаются в едином списке.
Нормативный контекст передаётся полностью и дословно.

Структура каждого пользовательского сообщения:

```text
ПРАВИЛА РЕШЕНИЯ
[Общие правила и определения ответов]

ФОРМАТ ОТВЕТА
[Формат для open или MCQ]

НОРМАТИВНЫЙ ТЕКСТ
[Только grounded: исходный context]

ОБЛАСТЬ РАССМОТРЕНИЯ
[Исходная первая строка case_text]
[Исходная область рассмотрения]

ОБСТОЯТЕЛЬСТВА
— [Исходные обстоятельства в исходном порядке]

ЗАДАНИЕ
[Исходный target]

[Только MCQ: исходные варианты с буквами]

[Короткая завершающая инструкция]
```

Общие инструкции повторяются в демонстрациях и текущем задании.
Сохраняются multi-turn few-shot, k=0/5 и порядок основной пятёрки.
Вынос правил в системное сообщение и изменение демонстраций не входят
в эту реализацию.

## Правила и ответы

Общие правила требуют:

- отвечать в пределах указанной области рассмотрения;
- не заменять «не указано» на «нет»;
- учитывать только допустимые сочетания неизвестных обстоятельств,
  совместимые с остальными условиями и применяемыми положениями;
- при одинаковом ответе во всех вариантах выбирать этот ответ;
- при разных ответах выбирать «недостаточно данных»;
- не смешивать неизвестность существенных фактов с неуверенностью в знании нормы.

В grounded приведённый нормативный текст имеет приоритет над запомненной редакцией.

Для бинарных задач «да» означает утвердительный ответ во всех допустимых
вариантах, «нет» — отрицательный во всех. Определение «не следует из указанной
нормы» бинарным задачам не показывается.

Для числовых и категориальных задач различаются конкретный результат,
отсутствие запрошенного результата по указанным положениям во всех вариантах
и различие результатов между вариантами. Сочетание конкретного результата
в одном варианте и «не следует из указанной нормы» в другом означает
«недостаточно данных».

### Числовой open

Три равноправные формы ответа перечислены до требований к записи числа:

- число;
- «не следует из указанной нормы»;
- «недостаточно данных».

Требования к цифрам и единицам начинаются словами «Только для числового ответа».
Число выводится без названия единицы, точно, без округления; допускаются
целая, десятичная и дробная запись. Для долей разрешены проценты;
для лет и месяцев запрещён перевод в дни. Метаданные единицы читаются
из `gold.unit`, значение `gold.value` не используется для выбора инструкции.

### Категориальный open

Форма записи задаётся постоянной таблицей по семейству, одинаковой
для всех случаев и не зависящей от фактов или gold:

- `gk:186`: «1 год», «до отмены», «ничтожна»;
- `gk:163`: «ничтожна».

Обе специальные формы ответа описаны общими правилами.
Неизвестное категориальное семейство в open вызывает явную ошибку.

### Без assistant-prefill

В open завершающая инструкция:

> Выведите только ответ в указанном формате, без объяснения.

В MCQ определения относятся к содержанию вариантов. Требования
печатать число или статус исключены. Сохраняются варианты, порядок,
буквы и эталонная буква; итоговая инструкция:

> Выведите только букву выбранного варианта.

MCQ-демонстрации содержат assistant-ответ только из буквы. Последнее
сообщение текущей задачи — `user`: нет ни `Ответ:`, ни пустого assistant.
Для open также нет содержательного assistant-prefill.
В обоих форматах получается `2k + 1` сообщений.
Штатное оформление начала ответа модельным шаблоном, включая foundational
`Response:`, сохраняется.

Метод MCQ остаётся `calculate_tokens_proba`; кандидаты и скорер прежние.
Опциональный open-judge получает новый фактический текст задания.

## Проверки и границы

Целевые проверки охватывают все 525 записей, четыре представления,
0/5-shot, сохранение содержательных блоков и данных оценки, отсутствие
зависимости пользовательского текста от скрытого ответа, совместимость
форм ответа со скорером, provenance/cache и отказ при повреждённой структуре.
Полный размер сообщений учитывается до запуска: демонстрации и нормы
не обрезаются при переполнении.

Проверки реализации не являются сравнительным экспериментом по качеству.
Его постановку и проведение определяет автор; в эту работу он не входит.
Возможное повышение метрик не считается установленным результатом.
